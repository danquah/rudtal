# Rudtal Flux boundary

This directory is the Flux sync root for the `rudtal` cluster. S06 establishes
Git-controlled Kubernetes add-on management while the cluster remains on the
known-good Talos and Flannel baseline. Cilium is an S07 experiment with a
separate reviewed design and physical runbook; Tailscale remains out of scope.

## Repository layout

```text
clusters/rudtal/
├── flux-system/                 # generated by `flux bootstrap git`
│   ├── gotk-components.yaml
│   ├── gotk-sync.yaml
│   └── kustomization.yaml
├── infrastructure.yaml          # Flux Kustomization objects
└── apps.yaml                    # Flux Kustomization object
infrastructure/
├── controllers/
│   ├── kustomization.yaml
│   └── cilium/                 # S07 experiment branch only
│       ├── kustomization.yaml
│       ├── cilium-source.yaml
│       ├── cilium-release.yaml
│       └── values.yaml
└── configs/
    └── kustomization.yaml
apps/
└── rudtal/kustomization.yaml
```

Flux bootstrapping owns the generated `clusters/rudtal/flux-system/` files.
The two cluster-level declarations are hand-maintained and point at the root
`GitRepository/flux-system` created by bootstrap. Empty Kustomize directories
are intentional until a platform component or application has a reviewed
version and rollback path.

## Ownership boundary

| State | Owner | Rule |
|---|---|---|
| Talos OS, boot, disks, hostname, node networking, kubelet and machine API | Talos configuration under `talos/` and authenticated `talosctl` | Change through reviewed Talos patches and the existing installation/recovery procedure. Flux must not edit these resources. |
| etcd, API server, scheduler, controller manager, static control-plane pods and Kubernetes bootstrap | Talos and exactly one bootstrap per fresh cluster generation; initial generation is S03, rebuilds are deliberate S07B/S09 steps | Never re-bootstrap an initialized generation. Use Talos for control-plane recovery. |
| Flannel CNI and the current node-level networking baseline | Talos/Kubernetes baseline | Do not replace Flannel in S06. Cilium is a separate disposable S07 rebuild. |
| Flux controllers, GitRepository, Kustomizations, HelmRepositories, HelmReleases, namespaces and applications | Flux from this Git repository | After bootstrap, commit changes to Git and let Flux reconcile them. |
| Kubernetes Secrets containing application or add-on credentials | SOPS-encrypted manifests under `infrastructure/` or `apps/`, decrypted by kustomize-controller | Encrypt only `data` or `stringData`; never commit plaintext or apply the encrypted file directly with `kubectl`. |
| Emergency live repairs | Operator, temporarily | Suspend the narrow Kustomization, make the smallest imperative repair, record it, then commit the equivalent Git change and resume. |

A Kubernetes object is Flux-owned only when it is in a reconciled path. Talos
resources and generated client credentials remain outside this boundary.

## Reconciliation and ordering

The bootstrap-generated `flux-system` Kustomization first makes the cluster
root available. It then applies these Flux Kustomization objects:

flux-system
    ↓
infra-controllers  (./infrastructure/controllers)
    ↓
infra-cilium      (./infrastructure/controllers/cilium; S07 branch only)
    ↓
infra-configs     (./infrastructure/configs)
    ↓
apps              (./apps/rudtal)

Each child uses `prune: true`, `wait: true`, a ten-minute interval and a two-minute
retry interval. `dependsOn` prevents configuration from racing a controller or
applications from racing infrastructure. New Helm releases must use a pinned
chart version, pinned values and a documented dependency; use OCI digests for
images where practical and avoid `latest` tags.

## Flux version and local CLI

The pinned release is Flux `v2.9.5`, published 2026-08-31. The official Darwin
arm64 archive SHA-256 is:

```text
2869ef7151a6f1b27e6b5d2a6804f3ef23c7bdaa06a74e00d3fe5bfc646547fd
```

The pinned CLI is installed locally at `$HOME/bin/flux`. The following is the
recorded, repeatable installation procedure; run it only when the pinned binary
is absent or deliberately replaced. It contacts GitHub and changes local
software, so the operator must approve it first:

```sh
set -eu
FLUX_VERSION=v2.9.5
FLUX_ARCH=arm64
FLUX_SHA256=2869ef7151a6f1b27e6b5d2a6804f3ef23c7bdaa06a74e00d3fe5bfc646547fd
tmp_dir="$(mktemp -d)"
trap 'rm -rf "$tmp_dir"' EXIT
curl --fail --location --proto '=https' --tlsv1.2 \
  --output "$tmp_dir/flux.tar.gz" \
  "https://github.com/fluxcd/flux2/releases/download/${FLUX_VERSION}/flux_2.9.5_darwin_${FLUX_ARCH}.tar.gz"
printf '%s  %s\n' "$FLUX_SHA256" "$tmp_dir/flux.tar.gz" | shasum -a 256 -c -
tar -xzf "$tmp_dir/flux.tar.gz" -C "$tmp_dir" flux
mkdir -p "$HOME/bin"
install -m 0755 "$tmp_dir/flux" "$HOME/bin/flux"
"$HOME/bin/flux" version --client
```

The checksum must match before installation. Do not use an unpinned package
manager install for this cluster.

The Markdown command fences in this document are deliberately complete: each
opening fenced block for `text`, `sh`, or `yaml` has its matching closing fence.
Keep commands in their fenced blocks when editing this operational document.

For S07, read [the Cilium design](../../S07A_CILIUM_DESIGN.md) before
[the destructive rebuild runbook](../../S07B_CILIUM_RUNBOOK.md). The latter is
not an authorization to perform the rebuild.

## Bootstrap exception and credentials

The initial bootstrap is the only planned break from Git ownership. It requires:

- cluster-admin access through `state/kubeconfig`;
- an existing Git repository and its SSH URL supplied by the operator;
- an SSH agent with local push rights for the bootstrap commit; and
- approval to create the Flux in-cluster Git credential.

Preferred bootstrap uses the SSH-agent flow. It avoids putting a personal access
token on the command line. Flux generates a dedicated cluster SSH key, stores the
private half and known-host data in the `flux-system` Kubernetes Secret, and
prints a public key for registration as a repository deploy key. Register that
key with read-only access for steady-state pulls; the local operator's agent
provides push access for reviewed changes.

Once the CLI is installed, the remote URL is supplied, and the operator has
approved the concrete action, the command is:

```sh
KUBECONFIG=state/kubeconfig "$HOME/bin/flux" bootstrap git \
  --url=ssh://git@<host>/<org>/<repository>.git \
  --branch=main \
  --path=clusters/rudtal \
  --version=v2.9.5 \
  --network-policy=true \
  --watch-all-namespaces=true
```

`--path` scopes Flux to this cluster; `--version` pins the generated controller
manifests; `--network-policy` keeps the controller namespace isolated by the
bootstrap defaults; and `--watch-all-namespaces` is required for this lab's
cluster-wide infrastructure and application paths. The command creates the
`flux-system` namespace, CRDs, controller Deployments, Git source, root
Kustomization and generated non-secret YAML, then pushes the bootstrap commit.
It changes both the Kubernetes control-plane state in etcd and the Git
repository. If it fails, retain the command output without printing credentials,
inspect Flux status, and do not use `--force` until ownership is understood.

The generated `flux-system` Secret is credential-bearing and must never be
committed or displayed. Rotate it by changing the repository deploy key and
recreating the Secret through the documented Flux credential command; do not
copy it into Git.

## Encrypted Kubernetes Secrets

No Kubernetes Secret is created by S06. The repository SOPS policy covers future
`*.sops.yaml` files under `clusters/rudtal/`, `infrastructure/` and `apps/`; only
`data` and `stringData` are encrypted. The Kubernetes kind, metadata and wiring
remain visible so Kustomize can build the object. The scoped rule currently
reuses the existing public recipient only as a policy scaffold; no Secret file
uses it.

Before the first real add-on Secret, replace that rule with a **dedicated Flux
SOPS age recipient**, keep its private identity outside Git, and back it up
separately. Do not load the Talos cluster identity into kustomize-controller.
The one-time operator exception creates the private key as `sops-age` in
`flux-system`; the Flux-owned Kustomization then enables:

```yaml
decryption:
  provider: sops
  secretRef:
    name: sops-age
```

The private key must travel only through the approved local secret-handling
workflow. A safe authoring pattern is:

```sh
kubectl -n <namespace> create secret generic <name> \
  --from-literal=example=placeholder \
  --dry-run=client -o yaml > /tmp/<name>.yaml
sops --encrypt --in-place /tmp/<name>.yaml
mv /tmp/<name>.yaml infrastructure/configs/secrets/<name>.sops.yaml
```

Replace the placeholder locally before encryption, never commit the plaintext
file, inspect only the encrypted structure, and never run `kubectl apply` on the
encrypted manifest. Flux decrypts it immediately before apply. The temporary
file must be removed after encryption. The example is procedural only; no
credential or Secret is present in this repository.

## Emergency changes and rollback

Normal changes are pull-request or reviewed-commit changes to Git. For an urgent
repair, first suspend the narrow owner:

```sh
KUBECONFIG=state/kubeconfig flux suspend kustomization <name> -n flux-system
# make the smallest necessary kubectl repair
# commit the equivalent desired state to Git
KUBECONFIG=state/kubeconfig flux resume kustomization <name> -n flux-system
KUBECONFIG=state/kubeconfig flux reconcile kustomization <name> -n flux-system --with-source
```

Record the reason, live command, resulting object and Git commit. Do not suspend
the root Kustomization for routine work. Reverting the Git commit is the normal
rollback; with `prune: true`, removed declarations are removed from the cluster
on the next successful reconciliation. For an unsafe change, suspend first,
revert Git, reconcile, then verify resource health and controller conditions.

Removing Flux itself is a separate recovery operation, not a routine rollback:
archive the Git history, ensure workloads have an intentional owner, then use
`flux uninstall --namespace=flux-system` and verify that the Flux namespace and
CRDs are gone. This discards Flux control-plane objects and must not be confused
with reverting one add-on.

## Verification evidence

After bootstrap, verify the boundary with:

```sh
KUBECONFIG=state/kubeconfig flux check
KUBECONFIG=state/kubeconfig flux get sources git -A
KUBECONFIG=state/kubeconfig flux get kustomizations -A
KUBECONFIG=state/kubeconfig kubectl get pods -n flux-system
```

For the S06 disposable check, commit one harmless ConfigMap under
`apps/rudtal/`, reconcile `apps`, change only that live ConfigMap imperatively,
and run `flux reconcile kustomization apps --with-source`. The expected proof is
that the Git value replaces the live drift. Delete the test declaration and
reconcile again because the resource is intentionally disposable.
